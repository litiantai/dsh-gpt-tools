# task-breakdown

依据已确认需求和技术设计形成可执行任务。任务不是无约束待办清单。

## 适用请求

复杂需求实施前、跨模块并行、技术返修计划。小改动可使用一个任务。

## 拆解

读取 [任务结构](references/tasks.md)。按可交付修改拆分，每项写目的、具体范围、输入版本、依赖与完成判据。测试和集成工作绑定实际验收条件，避免“完成开发”“全面优化”等不可验收描述。

共享文件、接口或工作区的任务不能误标为可同时写入。任务顺序由依赖决定；模型建议不直接改变平台运行状态。

## 验证

检查需求验收都有任务落实，任务没有新增未经确认的需求，依赖无环，任务量与复杂度相称。使用当前平台输出契约：仅有 plan 时在 plan 内写任务章节；有 task_breakdown 或 tasks 字段时使用对应结构。下面脚本的 tasks 是离线检查输入，不表示平台自动执行了任务图。

- [检查依赖与覆盖](scripts/validate_tasks.py)：JSON stdin 检查任务标识、缺失依赖、循环和验收覆盖。
- [任务文档参考](assets/TECHNICAL_TASKS.md)：按实际任务填充，不使用空表作为完成产物。
