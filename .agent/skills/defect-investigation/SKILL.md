# defect-investigation

依据监控、日志、源码和复现记录分析实际问题。不能把启动失败、超时或一张截图直接认定为业务缺陷。

## 调查

使用 [证据与归因](references/investigation.md) 对照运行身份、版本和已有需求。说明观察到的行为、复现步骤、影响、根因证据和待调查假设。相同原因合并，不因未上线的修复将线上问题标为解决。

## 结果

确认存在问题时形成有验收标准的需求建议；环境障碍写恢复条件。无新问题返回有依据的 no_issue，不制造改动。协调建议只能依赖真实检查变化。
