# 需求文档

包含目标与用户、场景、范围与排除、交互与状态、验收条件、影响、来源、假设与未决问题。只包含此需求有用的信息。

截图改动要写清哪些视觉元素是参考、哪些行为必须一致；正常、加载、空数据、失败等状态按实际功能覆盖。接口、人员、预算、Jira 链接未知时不要虚构。

结构化字段 title/goal/scenario/scope/acceptance/evidence/impact/questions 是平台的可验证核心；target_requirement_id 仅用于修改本次对话已展示的需求，新建时为空。观察、推断、排除范围和完整说明使用对应字段或 summary 表达。以当前平台 Schema 为准，不自行添加 document、image_observations 等未提供的输出字段。
