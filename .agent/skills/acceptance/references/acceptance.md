# 验收矩阵

需求版本与验收条件标识 → 操作/检查 → 实际结果 → 当前提交证据 → 判定。

每项条件都需要结果；unknown 不等于 pass。新版本、新配置或源码变化使旧回执失效。业务通过、交付、上线是不同平台状态。

流程修复逐项核对原需求的 development_guidance、coordination_help_plan、acceptance 与 resolution_probes，检查新增定向回归、真实记录/响应及其当前候选提交。登记的 check 入口必须实际执行新增用例；固定 pass 标志、泛化绿色 suite 和开发摘要不能代替效果。遵守平台测试执行模式，控制器已完成的检查不重复运行。候选验证通过不代表发布后正式实例已通过。
