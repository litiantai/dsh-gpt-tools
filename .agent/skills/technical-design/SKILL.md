# technical-design

从已确认需求和实际代码产生可实施的技术设计。方案引用需求和已有设计版本，不扩大任务。

## 适用请求

实现前设计、复杂变更、跨仓库联动、依据失败证据重新设计修复。纯进度问题不使用。

## 设计过程

- 读取确认文档、项目规范、真实模块与验收条件；记录当前能力和需要增加的行为。
- 根据修改内容选择 [设计参考](references/design.md) 的章节。小改动允许短方案；没有数据、部署或缓存变化就不填无关模板。
- 界面设计覆盖关键操作与状态；接口设计根据真实调用方列请求、响应、错误和兼容方式。跨项目先确认参与者，UI 字段与 API 契约需互相对应。
- 方案说明改动、依赖、验证方法、风险与回退。返修逐项对应当前失败回执，不能把调度方案当技术修复方案。

## 交付与验证

plan 使用 Markdown，引用可读取的需求标识、版本和代码基线；技术设计与实施任务分别说明。当前平台仅提供 plan 字段时，把任务拆解放入 plan 的适当章节；只有 Schema 明确提供 task_breakdown 时才使用该字段。执行前检查范围与验收均有落实处。未调查的方案选择标假设，不伪造已运行的测试或独立文档版本。

- [设计文档参考](assets/TECHNICAL_DESIGN.md)：按修改内容使用章节；模板不代替项目调查。
