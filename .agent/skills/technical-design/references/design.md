# 按需技术设计参考

整体思路：当前行为、目标行为、涉及模块与协作边界。

前端：界面字段、交互、状态、路由与数据依赖。

后端：接口契约、核心逻辑、状态与幂等、数据库或缓存变更、容错、需要新增的监控。

部署：仅在涉及部署时说明切换、兼容、灰度、回滚；指标、人天和系统容量用真实依据，缺失就明确待评估。

验证：每项验收到具体检查与证据路径的对应关系。

内部流程修复：保留原需求中的 development_guidance、coordination_help_plan、acceptance 与 resolution_probes，逐项安排产生缺失的归因回执、路线定义、请求响应留存或断言。说明修复前失败条件、候选修复后读取的实际记录、定向回归和正式实例复验边界；缺失未来字段不要求先证明应用 bug，不以泛化绿色 suite 代替效果验证。
